# 毫米映射与高性能可视化验收

任务日期：2026-11-11。范围：全部7个已审查模板的二维至三维映射、工作台交互、可逆拾取、显示精度、渲染架构与验收范例。

本轮工程检查通过，**真实浏览器画面、硬件 GPU 性能和实体尺校准尚未验收**。当前三维仍是平面裁片的空间预置，不是缝合后的服装或布料仿真。

## 一、尺寸依据与映射合同

### 1. 原始毫米数据是尺寸依据

制版输入、源曲线、源边长度、展开二维坐标、刚性放置和测量均使用 JavaScript 双精度数值及毫米单位。GPU 的 Float32 缓冲只负责显示，不回写制版数据。glTF 的 POSITION 使用米，转换为 mm/1000；源二维追溯属性继续明确使用毫米。

三维网格来自结构源轮廓。普通裁片为净轮廓，包条为源展开裁边；不自动添加普通缝份、布厚或不存在的缝合完成态。数量严格来自裁剪指令。副本不凭数量推断左右、内外层或配缝方向。

每个网格顶点保留源身份、源边、曲线参数 t、原始二维毫米、展开二维毫米和三维毫米。裁片表格分页展示，每页最多 50 行，不为全部顶点创建页面节点。

### 2. 前向转换

完整链路：

`源二维 mm → 显式折边展开 → 展开二维 mm → 刚性放置的三维 mm → 正交相机 → CSS px → 渲染设备 px`

展开点为 (x,y)、绕 Y 轴角度为 a、平移为 (tx,ty,tz) 时：

```text
X = x*cos(a) + tx
Y = -y       + ty
Z = -x*sin(a)+ tz
```

Y 取反是二维图纸向下与三维向上坐标的明确约定，不是拉伸。相机另行保存中心、旋转、俯仰、CSS px/mm 和屏幕平移。相机水平单位向量 R、竖直单位向量 U、中心 C、显示倍率 s：

```text
screenX = width/2  + panX + dot(P-C,R)*s
screenY = height/2 + panY - dot(P-C,U)*s
```

拖动旋转、筛选和后续视口变化不重算 s；放大/缩小、滚轮、明确适配/聚焦、预设视图或实体比例设置可以改变 s。首次测得真实视口尺寸时适配一次。当前片正视同时适配当前裁片；预设视图同时适配可见裁片。适配采用投影边界的84%占用率，不以球半径把图纸缩成小块。所有模型尺寸独立于相机。

### 3. 反向拾取与量尺

屏幕点先反投影为双精度射线，与可见裁片平面求交。先检查缓存的局部包围盒，再计算三角面的重心坐标，读取原始展开二维坐标，并经源折边反射回原始半片。

对跨越折边的三角面，不能直接插值原始半片坐标：那会使宽度塌缩。实现先插值展开坐标，再依据显式折边和源半片方向做逆变换。专项检查覆盖了这种情况。

页面展示实例、源身份、三角面、重心坐标、展开二维、源二维和三维坐标；内部面上的点不伪造源边或曲线 t。

- 同一物理裁片两点：读取材料平面的直线距离及三维直线距离。
- 不同物理裁片两点：只称空间间距，不作为服装尺寸。
- 源轮廓边长度：读取源曲线长度，区别于网格弦长、两点直线或包围框。

点击位置受到像素和倾角限制；显示三位小数不意味着人工点击具有 0.001 mm 的定位能力。严格尺寸应以源定位和源轮廓长度核对。当前为刚性平面，同片三维直线与平面直线相等；未来布料变形后须另行定义材料距离与空间距离。

## 二、屏幕实体尺寸怎样成立

浏览器的 CSS px、CSS mm 和系统缩放都不能直接当作实体毫米。DPR 只决定渲染采样密度，不决定模型尺寸或用户显示器的实际像素间距。

页面提供 220 CSS px 的标尺，由用户用实体尺测量。实测 L mm 后，校准值为 `220/L CSS px/实体 mm`。例如实际读数 55 mm，则为 4 CSS px/mm；100 mm 的模型线在该显示条件下应占 400 CSS px。

“实体 1:1”按钮需要同时满足：已完成当前显示条件下的校准、当前裁片为正视。按钮设置相机显示倍率，保持模型尺寸原值。大裁片可能超出视口，可平移查看，不能为了塞进画面再次缩放后仍称 1:1。

校准只保存在当前三维会话；几何版本变化会重置。DPR、屏幕尺寸、可用区域或浏览器视口缩放变化时失效。浏览器可能无法区分两台同规格显示器，**换屏必须重新用实体尺校准**。实体尺和读数本身的误差也会影响结果；本轮没有进行实体校准实验。

倾斜裁片会投影缩短，“实体 1:1”只针对正视的当前裁片平面。视平面毫米标尺与裁片沿曲面的实际长度不是同一个量。

## 三、精度分层与阻断条件

统一配置位于 `src/lib/pattern/mesh/precision-policy.ts`。这些是本原型的数值与显示预算，不是行业标准或生产公差。

| 层级 | 当前检查 | 失败处理或边界 |
|---|---|---|
| 源制版数据 | 原有完整输入、源版本、结构与配缝检查 | 缺数据或结构阻断时撤图 |
| 刚性映射 | 往返及边长失真不超过 0.000001 mm | 不能生成网格 |
| 曲线显示离散 | De Casteljau 控制凸包至弦段误差限 0.05 mm，边界采样跨度不超过 20 mm | 不收敛即阻断 |
| 面积守恒 | 源曲线与多边形面积误差不超过 0.1%；三角化面积守恒 | 不符合即阻断 |
| 局部显示缓冲 | 居中后的 Float32 坐标转换误差不超过 0.001 mm | 超限阻断 |
| 实例与轮廓 | CPU Float32 运算探针对实例矩阵、轮廓缓冲的量化估算不超过 0.01 mm | 超限阻断；不当作实测 GPU 误差 |
| 屏幕采样 | 显示一个渲染像素对应多少视平面 mm | 与相机倍率、封顶后的 DPR 联动 |
| 实体显示 | 实体尺校准，并正视目标裁片 | 未校准不宣称实体比例 |

显示缓冲先按源几何局部中心平移，再相对场景中心放置，以避免巨大的世界坐标降低 Float32 精度。量化检查包含实例矩阵与批量轮廓，不能只检查局部顶点。测试既覆盖整体平移 10^12 mm，也覆盖实例间距过大时必须阻断的情况。

上述预算不能简单相加后宣称制造精度。实际 GPU 着色、矩阵运算、光栅覆盖和屏幕量测仍需真实设备实验；源制版规则及身体测量的专业适用性另行审核。

## 四、性能架构

1. 使用 Three.js **0.187.0（MIT）** 的 WebGL2 渲染。每个源裁片一份顶点与索引，物理副本通过 InstancedMesh 批量绘制。默认实体批次数按源种类增长，统一轮廓另用一个批次；三角网格可选显示。
2. 旋转只更新相机矩阵，不生成裁片、不三角化、不重传顶点或实例矩阵。筛选更新实例可见列表和轮廓索引，原始裁片不变。静止时没有持续渲染循环，同一批操作合并到一次绘制。
3. 生成、检查和缓冲准备进入独立模块 Worker。传输显示用数组，原始双精度 CAD 不被转移或清空。只有同一请求编号与几何版本的回复可以呈现；切换输入立即撤掉旧图，取消任务不能恢复旧图。
4. Worker 不可用时明确报错；没有隐藏的主线程同步生成降级。无 WebGL2 时使用按裁片合并路径的 Canvas2D 兼容模式；两种上下文均不可用或绘图异常时自动切换SVG投影，继续共用源毫米坐标、相机与拾取。兼容模式不承诺硬件帧率。
5. DPR 最大按 2 渲染，兼顾高密屏与填充成本。渲染像素精度使用实际采用的 DPR 计算，不把设备 DPR 全额计入。
6. 三维模块单独延迟加载；卸载释放 Worker、GPU 资源、观察器、监听器和待绘制帧。图形上下文丢失时自动转SVG投影，手动重试使用新画布并保留相机和源数据。组件清理不主动切断可能被React复用的画布连接。
7. 实体使用计算法线和粗糙材质、主光/补光及毫米地面网格；选中轮廓橙色高亮。地面网格和相机不写回裁片模型，导出仍包含完整模型。相机、渲染和SVG拾取统一使用Y向上坐标。

正式构建包含独立三维模块约 564 kB、后台网格模块约 447 kB，主入口约 1,063 kB，均为构建文件体积（未 gzip）。仍有大包提示，不能把延迟加载当成已经完成所有性能优化。Canvas2D 兼容模式也不承诺大网格帧率。

### 操作人员的真实设备验收步骤

1. 打开顶部“3D 映射”，默认Brian应直接显示4片；再选择包边背心、连帽卫衣，核对数量为5、14，且渲染模式为WebGL2或明确的兼容模式。
2. 旋转并调整窗口宽度，确认显示倍率不自动改变；放大后筛选包条或罗纹，确认只显示匹配实例。清空筛选时恢复正确数量。
3. 点击当前片正视，启用量尺工具后选择两个位置，核对源数据和读数；另选曲线边，核对源弧长。跨片量尺须标为间距。
4. 实体尺测量 220 CSS px 标尺，输入实测值，再切换实体 1:1。以独立已知长度复测；记录显示器、系统缩放、浏览器缩放、尺具与偏差。换屏或缩放后重新校准。
5. 在真实硬件记录旋转帧时间、绘制批次、内存及连续切换后的资源情况；大网格另设实测验收阈值。当前未建立硬件帧率基线。
6. 保存旋转前后及筛选前后的实际界面截图。`npm run e2e:3d` 包含9步真实操作、视口画面前后比较、隔离/隐藏、连接丢失、真实点击量尺与重试；总工作流 `npm run e2e` 也更新了折叠检查项的操作。本轮只做语法检查，未执行浏览器脚本。
