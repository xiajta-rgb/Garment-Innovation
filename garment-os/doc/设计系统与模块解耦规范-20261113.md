# 设计系统与模块解耦规范

## 目标

工作台的颜色、间距、圆角、控件高度、交互状态和导航文案由共享层维护。普通工作台使用统一白色界面，三维工作区单独使用深色视口和检查面板。业务模块只负责数据和业务动作，不再自行定义同一类按钮、区块或页面入口的视觉规则。

## 三层边界

1. **数据层**：`src/data` 与 `src/application` 保存品类、裁片、资产、导航和业务规则。数据对象使用稳定的 `id`，展示文案由配置提供；组件不复制同一份列表。
2. **组件层**：`src/design-system/components` 提供 `UiButton`、`UiSection` 等可复用交互组件。组件只接收状态、事件和内容，不读取具体品类数据。
3. **样式层**：`src/design-system/styles.css` 提供语义 CSS 变量和基础控件样式。亮暗主题只切换变量值，业务模块通过语义变量取色，不直接写主题色值。

## 当前接入

- 工作台主导航统一由 `src/application/workbench-config.ts` 提供，顶部栏不再维护重复文案数组。
- 顶部栏的保存、导出、撤销、重做按钮统一使用 `UiButton`。
- 左侧所有折叠区统一使用 `UiSection`，并生成可访问的 `aria-controls` 关联 ID。
- 旧的 `shared-styles.ts` 只保留兼容导出，新组件应直接使用设计系统组件和 `designTokens`。
- 白色界面的语义变量、间距、圆角和控件高度集中在 `design-system/styles.css`；三维深色变量只在 `.mesh-workbench` 内声明；`index.css` 只保留全局重置和第三方组件覆盖。

## 扩展规则

- 新增按钮先选择 `primary`、`secondary`、`ghost`、`danger` 或 `toggle`，只有出现明确的新交互语义时才扩展变体。
- 新增导航先写入配置，再由页面根据 `id` 分派动作；不要在 JSX 中复制导航数组。
- 新增颜色、间距和状态先增加语义变量，再在组件中引用；不在业务组件中新增同义的十六进制颜色。
- 业务数据的空值、待核验和不可用状态继续由数据层表达，设计系统只负责一致地呈现状态，不替业务数据做默认填充。
