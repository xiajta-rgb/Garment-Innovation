# 成熟制版项目调研、参数能力与三维映射验证

本轮已将两套有固定源版本的完整制图方法接入运行系统，并实现二维裁片到三维网格的数据转换。结论限定为**参数化参考制图与三维映射可行**；三维成衣缝合、垂坠、合体和制造交付均未验收。

## 二、本轮新增的真实生成能力

### 1. 包边背心 · Aaron

- 4种源裁片：前身、后身、领口四折包条、袖窿四折包条；实际裁剪为5片。前后身各裁1对折，袖窿包条裁2，领口包条裁1。
- 开放5项源参数：衣身负松量、前领口下降、肩带宽度、肩带位置、包条展开宽倍率。
- 包条长度由实际领口/袖窿曲线积分驱动，源比例为开口长的95%。该比例是设计假设，未冒充材料实测。
- 展开宽默认60mm，四折完成宽15mm；源包条矩形就是裁边，不再虚构一道10mm普通缝份。折线与下料对折分别管理。
- 领口弯曲参数锁定源默认值1。其他值未获独立关系核对，不开放给用户自由变形。
- 肩缝和侧缝已明确端点与走缝；包条端头连接、有效闭合环长、材料验证与完成态仍待实现。

### 2. 开襟连帽卫衣 · Huey

- 7种源裁片：前身、后身、袖片、前半袋、帽侧片、罗纹下摆、罗纹袖口；实际为14片。
- 数量依次为2、1对折、2、2、4、1、2。帽裁4片来自同面料双层构型，不把它伪装成独立异材帽里。
- 开放12项源参数：罗纹开关、贴袋开关、罗纹高度/设计缩率、帽高/帽口后退/闭合高度/后深/底边角度、袋高/宽/开度。
- 独立头围直接控制帽部；帽底由前后领窝实长驱动。不用颈围或胸围估算头围。
- 罗纹条长为装接净长×(1−设计缩率)，默认设计缩率15%；改变罗纹高度同时改变衣身与袖片长度。
- 关闭罗纹撤去两种片；关闭贴袋撤去袋片、前身定位线和配套接口。源裁片种类依开关变为7/6/5/4种。
- `waistband`在此方法中明确绑定“下摆罗纹”，不按英文名称误归裤裙腰头。罗纹从`ribbing`主材料读取裁剪数量。
- 贴袋定位线是缝制位置，不是切口。袋口曲线、袋顶/袋侧、袋底/前中心共缝区分别管理。

关闭贴袋的测试发现：Huey 4.10.2会返回继承前身的未隐藏轮廓。适配器只在源`pocket=false`时明确排除该失效部件，避免生成一块衣身形状的“假袋片”；没有修改已安装上游包。

两方法均支持保存/载入、撤销/重做、模板文件导入导出和组合规则导出。新增头围对旧模板保持可选；连帽模板缺头围时拒绝生成、保存输入解析及导入，不混入当前样本值。

### 3. 分类、材料与元素库

分类词典仍为22大类、129角色、7材料身份、13服装场景。可执行源身份由19增至30，已绑定角色由9增至15，覆盖大类由6增至10；**114角色仍只有分类定义**，没有伪装为已具备CAD能力。

原飞书本地快照维持30条结构记录，其中18条对应原19种源身份、12条隔离。新增11种源裁片和2个模板生成[本地待登记候选](evidence/capability-20261111/element-registration-candidates.json)，记录编号为空。本轮没有飞书写入，也没有重新宣称远端分类已核验。原有关联丢失依然报错，只有明确列出的新增源身份属于待登记。

新增6项工艺输入定义：包条端头方法、闭合损耗、材料验证后缩率、罗纹材料验证后缩率、罗纹折合容位、拉链完成长度。与现有材料测试方向、负荷、伸长、回复和缩水字段共同使用；**所有实测值保持未录入**。

## 三、二维到三维已实现什么

采用与GarmentCode相同的分层思路：源裁片局部二维坐标 → 网格 → 三维初始摆放 → 实际物理求解。当前完成前三个数据步骤。

1. 使用源净轮廓的真实直线和三次曲线；包条保留源展开裁边。用De Casteljau细分，控制曲线弦误差0.05mm，最长边采样跨度20mm。
2. 只依据已审查的唯一源折边展开对折片；保留展开前坐标及镜像分支。不从“裁2片”推断左右镜像。
3. 用Earcut三角化；仅删除数值零面积面，同时必须满足完整面积守恒。保留被采样边界顶点的源信息。
4. 每个源裁剪副本获得独立实例；记录源裁片、源边、曲线参数t、原始二维毫米坐标、展开后二维坐标及三维毫米坐标。
5. 三维仅进行刚性旋转和平移，按展开板摆放。该位置不是由人体计算的穿着位置。反向变换可恢复原二维坐标。
6. 背心前后身的左右肩缝、左右侧缝已有4组物理片对应，每组17个采样位置，保留源边和曲线参数。配缝位置在源曲线上；归一化弧长定位使用细分近似。显示的间隙是**未缝合初始间隙**。
7. 卫衣完成14片网格转换，但袖、帽的内外层、贴袋和罗纹的物理片缝合分配尚未实现，不输出假配对。
8. 自包含glTF 2.0使用米表示三维POSITION，`_CAD2D`与`_SOURCE2D`明确保留毫米坐标，节点附源曲线和顶点追溯。另可导出完整映射JSON。

前端入口：选择“包边背心 · Aaron”或“连帽卫衣 → 开襟连帽卫衣 · Huey”，进入“裁片库 → 三维映射”。可旋转、俯仰、点击选片、按现有分类筛选、查看顶点来源和导出。筛选改变实际网格；模板不支持或输入无效时撤去旧图形。

## 五、距离三维成衣和生产能力还差什么

1. **物理片分配**：在已登记数量基础上，显式确定左右、内外层及每次缝合的实际实例。背心只有肩/侧缝完成该项，其他对应继续待定义。
2. **完成态几何**：包条端头损耗、四折包覆、袋口翻折、袋底/拉链/下摆共缝、罗纹折合，必须先完成再求有效装接边。Simon袖口去褶后约−4.300mm差仍需重制，独立领底和袖衩翻折问题没有随本轮自动解决。
3. **仿真网格**：生成适合求解的内部网格、均匀边长和足够的折弯自由度，保留原始网格与CAD边的映射。当前长瘦三角面明确不作为布料求解网格。
4. **人体与预置**：建立独立人体网格、姿态、体表语义、真实围度和碰撞厚度；当前展开板不具有穿着合体含义。
5. **材料与求解**：建立经纬拉伸、剪切、弯曲、密度、阻尼、摩擦、厚度及单位合同，优先在隔离环境验证GarmentCode所用[NVIDIA Warp分支](https://github.com/maria-korosteleva/NvidiaWarp-GarmentCode)，对齐版本和依赖许可，不在前端自行拼一个未经校准的“仿真器”。
6. **量化放行**：定义缝合闭合残差、三角应变、穿透深度、稳定时间与样本标注，分别检查求解收敛与合体合理性。求解成功本身不等于生产验收。
7. **下装与更多结构**：先补裆深、内外长、腿围、腰臀平衡及裙长等测量语义，再接Paco/Sandy；不能用本轮114个仅定义角色作为完成数量。
8. **制造交换**：DXF-AAMA/ASTM、剪口钻孔约定、分幅比例、放码、排料和材料采购用量仍需独立实现和验证。

本轮验收边界：可接受“两个新增完整参考方法、参数与材料约束、可追溯三维网格及可读取导出”的工程结果；不得据此接受“所有裁片类型完整、所有部件任意组合、仿真合体或生产制造已完成”。
