# 三视图设计资产库架构

## 目标

设计台是创作入口，资产库是长期沉淀入口。用户点击顶部“保存并沉淀资产”或工作台 Save 后，当前设计中所有有裁片的方案都会写入 `designAssets`，每个方案单独形成一条三视图设计资产。原设计仍保留在 `designs`，资产通过 `sourceDesignId` 和 `sourcePlanId` 回溯来源。

## 数据边界

- `designs`：编辑会话、尺寸、工艺、企业面料关联和整份组合方案。
- `designAssets`：可检索的三视图组合资产，保存裁片组合快照、品类/基型、矩阵批次、标签、版本和审核状态。
- `fabrics` / 面料服务：面料主档和来源图片，不复制进设计资产。
- 后续 `assetRenders`：三视图 SVG/PNG、面料高清图和森灵结果的资源引用。设计资产只保存引用 ID 或 hash，避免每款重复嵌入大文件。

## 生命周期

1. 设计台保存：写入设计记录，并为每个非空方案建立或更新资产。相同来源设计和方案使用稳定资产 ID，保存会递增 `version`。
2. 资产库：按名称、标签、基型、矩阵批次、审核状态检索；点击资产可查看三视图并载入设计台继续编辑。
3. 删除：普通删除只把 `status` 改为 `trash` 并记录 `deletedAt`，不丢数据。
4. 恢复：垃圾桶中的资产恢复为 `active`，版本递增。
5. 永久删除：单独操作 `purge`，删除后不提供恢复承诺。

## 审核边界

新资产默认 `reviewStatus=draft`；矩阵候选为 `exploration`；`productionApproved` 始终为 `false`。资产沉淀只代表设计表达和来源留痕，不代表净样、配缝、样衣或生产审核已通过。

## 批量与性能

- 资产列表只返回摘要，默认每页 24 条，最多 100 条；完整裁片组合按卡片点击读取。
- 三视图资源采用懒加载和引用去重，避免一次性把一万款的 SVG/PNG 转成 React 节点。
- 设计记录保存组合快照，图片和高清生图资源放入独立资源表/对象存储；同一资源通过 hash 复用。
- 资产库查询按 `status`、`categoryId`、`patternId`、`updatedAt`、`matrixBatchId`、`reviewStatus` 和 `tags` 建索引。

## 维护原则

来源设计删除不会连带删除资产；资产是可复用的长期记录。生产审核、版师审核、样衣验证和市场反馈在资产上继续追加状态与证据，不用覆盖原始设计快照。
