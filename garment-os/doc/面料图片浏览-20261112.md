# 面料图片浏览

## 问题与改动

原页面进入后只检查连接，不读取面料；列表没有图片列，详情只显示选中记录的小图，默认第一条恰好缺图。因此即使连接正常，也很难发现已有图片。

现在在原“资产库 → 面料库 → 面料管理”内提供图片浏览：

- 已连接时读取首页25条启用记录。首页仅在浏览器内存缓存5分钟，导航和React StrictMode复用同一读取；连接变更和读取失败会清除缓存。查询按钮可主动重新读取，不自动遍历全库。
- 默认显示图片卡片，并将本页有图记录排前。可切换带缩略图的列表，或勾选“仅看本页有图”；筛选仅影响已读取的这一页，不增加上游查询。页码、实际条数及有图条数分开显示。
- 无来源图片、加载中、加载失败分别提示；失败可手动重试。不用生成图片填充缺失值。
- 点击面料图查看来源原图。预览显示实际像素，支持适合窗口、50%/100%/200%缩放、滚动查看细节、打开来源原图、Escape关闭和返回触发按钮。
- 常用查询保留编码、名称；分类、功能、状态、季节、ID等收进更多筛选。
- 款式关联后，在设计台的面料摘要中显示各部位图片入口，可直接打开原图，与现有三视图设计一起使用。尚未做纹理贴合、物理仿真或森灵生图。

沿用现有工作台主题、导航与款式存储，不增加独立页面。来源图片URL原样使用，不推导“高清版本”或拼接CDN参数。图片不会改变裁片毫米尺寸。

## 核验与证据

本轮完成的面料浏览器回放使用4次真实有界只读查询：首页25条、第二页25条、FC-00315编码和精确ID；其中首页3条带图，第二页17条带图。FC-00315、FC-00318实际图片均为7008×4672，FC-00319为880×623。原图由真实浏览器成功加载并读取自然像素。

- `npm run check`通过：65个测试文件、1271项测试，含图片状态、首次读取复用、旧响应竞态、错误后重试和原图预览测试。
- `scripts/e2e-material-management.mjs`：8个浏览器流程通过，包含自动首页、真实图片、列表切换、本页过滤、原图缩放与焦点恢复、分页、条件查询、款式关联、撤销重做、保存重开、导出、设计台图片入口、深色与手机。权限失败场景使用明确模拟403，其余面料查询为真实接口。
- `scripts/e2e-workbench-ui-system.mjs`：9个原工作台流程通过。POST请求按路径区分，允许只读面料查询，其余POST须为零。
- 构建仍有已有的大文件体积提示；不影响此次通过结果。

真实响应、图片像素、款式保存回读与8步报告保存在 `doc/evidence/material-images-20261112/`；工作台9步报告位于 `doc/evidence/workbench-ui-system-20261112/browser.json`。
