# GarmentOS 基建优先级与仿真边界

## 目标

当前阶段先完成可持续扩展的服装研发系统底座，不以 CLO/Style3D 级别的物理准确度作为本阶段验收条件。

3D 能力先定位为“裁片装配与成衣外观预览”。它必须可追溯、可重复生成、可保存和可替换，但不宣称已经完成真实面料垂坠、人体试穿或生产批准。

## 本阶段的系统边界

### 必须完成

1. **统一业务数据模型**
   - 款式、模板、裁片、裁片角色、尺寸、结构部件、缝合关系、面料引用、工艺选择和版本必须有稳定 ID。
   - 原始输入、派生几何、显示几何和审核状态分开保存。
   - 所有长度、面积和位置的内部计算统一使用毫米。

2. **可组合的参数化计算层**
   - 参数、依赖关系、几何生成、部件接口和约束检查分层。
   - 参数变化后只重算受影响的裁片和下游结果。
   - 约束区分 `error` 和 `warning`；缺失值保持缺失，不能用默认零值伪造完成。

3. **裁片与装配关系**
   - 每个裁片保留源方法、源边、角色、数量和来源追踪。
   - 缝合关系记录两侧裁片、对应边、方向、长度差和当前状态。
   - 结构部件通过组件合同接入，缺少源裁法或接口时阻止装配。

4. **持久化、导入导出和版本兼容**
   - 设计文档可保存、恢复、复制、删除和列出摘要。
   - 读取旧数据必须经过 schema 校验；不完整的历史记录不得静默补齐。
   - 导出文件必须带 schema、版本、时间和来源信息。

5. **可替换的显示与仿真边界**
   - 预览渲染不能修改源 CAD 或裁片数据。
   - 未来的物理求解器必须通过独立适配层接入，不能把展示参数当作实测面料属性。
   - 当前成衣结果的状态保持为预览，除非未来获得单独的实物校准和专业审核证据。

6. **可验证的工程底座**
   - 保留架构审计、几何单元测试、存储测试、后台 Worker 测试和真实浏览器 E2E 测试的边界。
   - 离线 SVG/网格渲染只能证明计算路径可运行，不能代替浏览器验收或生产批准。

### 本阶段暂缓

- 高精度布料物理求解、复杂自碰撞和动态姿态仿真。
- 面料拉伸、弯曲、剪切和摩擦的实物标定。
- 真人扫描、人台压力图、真实试穿评价。
- 自动放码、自动排料和裁床级生产文件闭环。
- 多人实时协作、知识图谱推理和 AI 自动生成可生产纸样。

## 当前实现状态的正式语义

现有 `GarmentAssembly3d` 使用 `seam-constrained-preview` 阶段；`PatternMesh3d` 的 `simulationReady`、`drapeValidated` 和 `productionApproved` 保持为 `false`。这些字段是当前系统的能力边界，不应为了界面展示而改成已完成状态。

## 验收顺序

1. 架构无循环、核心模块可被真实入口引用。
2. 设计文档保存后可读回，schema 和版本检查有效。
3. 参数、尺寸、裁片、缝合和部件合同的输入输出可重复。
4. 裁片检查、装配预览、导出和恢复在浏览器中完成真实操作。
5. 所有预览页面明确显示“结构示意/仿真未标定/未生产批准”等状态。
6. 只有底座稳定后，再单独增加某一类服装的近似垂坠或物理求解能力。

## 对标原则

当前不追求复制 CLO/Style3D 的全部求解器能力，而是先建立三个可持续扩展的接口：

- `Pattern`：描述可编辑的源裁片和参数。
- `Assembly`：描述裁片之间的连接、方向和装配状态。
- `Preview/Simulation`：消费前两者并返回派生结果，不反向污染源数据。

只要这三个边界稳定，后续可以逐步替换渲染器、碰撞算法、面料模型和云端计算，而不重写设计台和数据层。
